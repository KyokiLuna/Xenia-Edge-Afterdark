Call-graph coverage index (priority modules only)
=====================================================
Regenerate with: python3 _tool/build_04_calls.py

Scope is intentionally limited to corpus_common.PRIORITY_MODULES
(XAM/avatar/gamer-profile/content/title-relevant modules).

Modules with >= 20 exports (xam.xex/$flash_xam.xexp) use
export-boundary-only coverage (reliable boundaries, large export tables
already give good coverage).

Modules with fewer than 20 exports additionally get
BFS-discovered internal-function coverage (capped at 250 functions,
reached via `bl` starting from the entry point, PLUS an opportunistic
callback-root expansion for *Register*-style imports) - these are
application-style modules (gamerprofile/createprofile/deviceselector/
signin/dash) whose real logic lives almost entirely in unexported
functions, so export-only coverage would find almost nothing. Each
function's calls/*.txt entry states EXACTLY how it was discovered
(export / bfs entry-reachable / callback root / callback descendant) -
only the function whose address was literally passed to a *Register*
import is labeled as a callback root; anything reached from it via
further `bl`s is honestly labeled a descendant, not another root.

build_05_strings.py (string xrefs) and build_06_ipc.py (IPC candidate
scanning) both reuse discover_module_functions() from this script, so
they see exactly this same function set, including callback
descendants - not a narrower export-only view.
